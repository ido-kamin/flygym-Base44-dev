# Base44 development environment

- This is a Python simulation library, not an API/database application. Its existing browser UI is the ProperDocs site with embedded MuJoCo-WASM apps. Serve the docs at `/`; standalone apps are `/wasm/viewer/viewer.html` and `/wasm/game/game.html`.
- Run `docker compose -f docker-compose.base44.yml up -d --build`. The one-shot `setup` service installs the frozen lockfile's `dev` extra and invokes the repository's existing asset hook. `web` waits for setup, syncs dependencies, then runs the live-reload documentation server on port 3000. Python dependencies and caches use named volumes; source stays bind-mounted and editable.
- No external credentials or database are needed. First setup needs public npm downloads for MuJoCo/Three.js. Browser models are generated locally; other optional Python workflows may lazily download public EPFL mesh assets.
- The image installs only the Python package manager and native graphics/video libraries; it does not bake application source. EGL supports headless MuJoCo imports and asset generation.
- `properdocs serve` watches `docs`, `wasm`, and `src`. WASM assets are generated only when absent: after changing model/controller configuration, run the relevant `scripts/dev/build_wasm_{viewer,game}_assets.py` with `docker compose -f docker-compose.base44.yml exec -T web .venv/bin/python ...`. The watcher then rebuilds the site. Generated assets/vendor files are already gitignored.
- Verify `docker compose -f docker-compose.base44.yml ps -a`: setup should exit 0 and web should be healthy. Curl `/` plus both standalone app pages, metadata files, and `/wasm/shared/vendor/mujoco/mujoco.wasm`. Served JS/assets should match checkout bytes; HTML differs because the dev server injects live-reload code. First docs build can take about 30 seconds and includes notebook conversion without execution.
- Asset generation includes a 2,000-step stability rollout for the game model. Browser/WebGL rendering still requires checking in an open preview tab; HTTP checks alone do not verify graphics or gestures.
- Python tests can run with `docker compose -f docker-compose.base44.yml exec -T web .venv/bin/pytest -m 'not warp and not rl and not tutorial and not network'`. GPU, RL and tutorial workflows need optional extras beyond this preview setup.
